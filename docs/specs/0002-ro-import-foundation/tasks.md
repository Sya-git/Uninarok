**How to use this file**
- Do tasks **in order**. One task = one reviewable commit. Tick the box in the same commit. Commit message format: `feat(0002): T1.2 implement RoPath` (CLAUDE.md §1.4).
- Each task lists the requirements it serves (`FR-n`) and a **Done when** check. Do not tick without verifying it and reporting the evidence (command and result).
- Tests come before implementation (red → green). A "tests" task is committed with its tests marked `[Ignore("pending Tn")]`; the implementation task removes the attribute and the tests must pass.
- Test command (batch): `Unity -batchmode -projectPath . -runTests -testPlatform EditMode -testResults results.xml -quit` (CLAUDE.md §2). "Tests pass" below means that command ends with zero failures.
- Steps that need the running editor (tests, refresh, manual checks) are run by the owner, or by Claude through a Unity MCP connection if the owner enables one.
- Paths are relative to `Uninarok-client/Assets/Editor/RoImport/` unless written in full. Class names and contracts are in `plan.md` §4; do not redesign them here.
- If a task needs a change not covered by the plan, stop and update `plan.md` first (CLAUDE.md §1.4 rule 6).
- Unrelated problems noticed on the way go to `docs/specs/BACKLOG.md` as one line each.
