## 1. Why

After SPEC-0011 the player can only hit with the weapon. Every job past novice lives on skills, monsters cast them too, and other players' skills fill every town and field. Today the client ignores all of it: a monster's Fire Bolt does damage nobody sees, a two-second cast looks like a frozen character, a Fire Wall blocks an invisible path. SPEC-0012 can play effects, SPEC-0013 can play sounds and SPEC-0014 holds what the client data and known facts say about each skill; this spec is the **behaviour** that joins them: the caster's motion, the cursor, the cast bar, the cast rules, the results, and the moment each effect and sound starts.

## 2. Goals

1. The own character knows its skills as the server sends them and uses them on a unit, on itself or on a cell, with the cursors of the client data and the server's cast rules.
2. Every skill in view shows its motion, cast bar, name, results, effects and sounds at the moments SPEC-0014's data and the server give.
3. Every skill-specific value comes from SPEC-0014's data, never from this spec's code; the behaviour is checked against Hercules and offline tests, and its look confirmed by the owner in game by screenshot, never by comparison with the original client.

## 3. Non-goals

- Skill data: decoding the client's skill data, the skill catalog (names, icons, kinds, hidden-name flags), the skill→motion table, the effect table by id, the skill→effect table by role, the refusal message table and the cast bar constants: SPEC-0014. This spec uses them as given.
- Importing, verifying and playing effects by path: SPEC-0012, which is skill-agnostic and addressed by path only (its warp portal files are only a visual test of the import). Game use of the server's effect packets (effect on a unit by id, level up, refine): out of scope (BACKLOG). Sound playback, volume and mixing: SPEC-0013. This spec only says which effect and sound start, when and where.
- Status-change visuals (status auras, the hidden look, status icons) beyond what a skill's effect row draws; the skill tree window, skill points, the real shortcut bar and skill descriptions are not part of this spec; nor is the chat window (FR-9's name is drawn over the caster, not logged).
- Item-given casts (scrolls, `autorun`), skill selection menus (Abracadabra, Auto Spell), combo chains, spirit spheres, homunculus, mercenary and pet skills; PvP and GvG targeting, as SPEC-0011.
- Client-side prediction of cast times, delays or damage: the client shows what the server sends.

## 4. Requirements

Priority: **M** = must, **S** = should. "SPEC-0014's table" means data owned by SPEC-0014, editable without code; this spec reads it and never holds a per-skill value of its own. "Dev only" means present only in editor and development builds, behind the project dev guard, and absent from release builds.

## 5. Success criteria

- From Bootstrap, on a local Hercules, with a swordsman, mage, acolyte and archer on prt_fild08: kill 10 monsters each with Bash, Magnum Break, Fire Bolt, Fire Wall and Double Strafe, heal with Heal, buff with Increase AGI and use Endure. No skill is refused for distance more than once per target, every cast bar lasts the server's cast time, no walk is sent during a cast without Free Cast, own SP equals `@stats` at the end, no skill unit stays in the model after its removal.
- A casting monster shows its bar, damage and effects.
- Every motion, effect, sound, refusal text and cast bar value seen comes from SPEC-0014's data; editing one of its rows changes what is shown with no code change. The FR-6, FR-11 and FR-14 offline tests pass; FR-18: 0 B per frame. The owner confirms motions, cast bars, effects and sounds in game, from screenshots saved with the evidence; nothing is compared with the original client.
- A release build has none of FR-2's command, hotkeys and list nor FR-17's HUD.

## 6. Assumptions and constraints

- References: Hercules (`skill.cpp`, `unit.cpp` `unit_can_move`, `clif.cpp`, `battle.cpp`, `db/re/skill_db.conf`, `conf/map/battle/skill.conf`) for rules; per-skill behaviour as SPEC-0014's data and reference note describe it; roBrowserLegacy a lead for facts only; the look is confirmed by the owner in game, not by running the original client (owner, 2026-11-24). Whether the server walks a player into skill range is checked in the plan; FR-4 assumes the client approaches.
- SPEC-0012, SPEC-0013 and SPEC-0014 come first; this spec adds no table, import or decoding of its own.
- Packets depend on PACKETVER 20220406, each checked against `packets_struct.h`, `clif.cpp` and a capture in the plan, docs in the same change. Expected: skill list `0x010F` (or newer), add `0x0111`, update `0x07E1`, removal, use failure `0x0110`, cast `0x0B1A`, cast cancel, damage `0x01DE`, position damage `0x0115`, no-damage use and heal `0x09CB`, ground use `0x0117`, unit entry `0x09CA`, unit removal, after-cast delay `0x043D`; out `0x0438` (to unit), `0x0366` (to cell).
- Skill names, icons, messages, motions, effect ids by role (resolved to parts, paths, wavs and timing by SPEC-0014's effect table by id) and cast bar constants from SPEC-0014; ids from the server. Actions and play-once from SPEC-0009; blow timing, numbers, walking into range and the SP bar from SPEC-0011; effect playback from SPEC-0012 and sound playback from SPEC-0013, unchanged.
- Game UI in UI Toolkit. Dev-only code (FR-2, FR-17) is compiled only under the project dev guard `#if UNITY_EDITOR || DEVELOPMENT_BUILD` and is absent from release builds (project rule).
